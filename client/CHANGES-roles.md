# ระบบบทบาท/สิทธิ์ + คำขอลบ + รูปกรรมการ/พนักงาน

แตก zip นี้ทับโฟลเดอร์ acr-management (ไฟล์ที่ชื่อซ้ำจะถูกแทนที่) ไม่มีไลบรารีใหม่ ไม่ต้อง npm install เพิ่ม

## ขั้นตอนติดตั้ง
1. สำรองฐานข้อมูลและโปรเจกต์เดิมก่อน
2. แตก zip ทับโปรเจกต์
3. `npm run db:init`  (schema.sql รันซ้ำได้ เพิ่มคอลัมน์ในตาราง users, ตาราง delete_requests, คอลัมน์รูปใน committees/employees)
4. `npm run build` แล้วรีสตาร์ทเซิร์ฟเวอร์
5. ล็อกอินด้วย admin จาก .env -> เมนู "จัดการผู้ใช้" -> สร้างผู้ตรวจ/ช่าง และกำหนดเมนู
   ผู้ใช้เดิมในตาราง users (ถ้ามี) จะเป็น "ทั่วไป" ที่ยังไม่มีเมนู ต้องตั้งบทบาทให้ใหม่

## บทบาท
- admin: ทุกเมนู ทุกอย่าง (บัญชี ADMIN_USER ใน .env เป็น admin เสมอ)
- inspector (ผู้ตรวจ): เฉพาะเมนูที่กำหนด ทำได้ทุกอย่างในเมนูนั้น รวมลบ อนุมัติปิดงานซ่อม ตรวจงานแม่บ้าน/คนสวน และอนุมัติคำขอลบ
- technician (ช่าง): เฉพาะเมนูที่กำหนด ดู/เพิ่ม/แก้ได้ ลบต้องส่งคำขอให้ผู้ตรวจอนุมัติ ตรวจงานและอนุมัติปิดงานไม่ได้
- staff (ทั่วไป): ดูอย่างเดียวในเมนูที่กำหนด

## กฎพิเศษ
- รายชื่ออาคารอ่านได้ทุกคนที่ล็อกอิน (READ_OPEN ใน server/access.js)
- ผู้ที่มีเมนูงานแม่บ้าน/งานสวน อ่านทะเบียนพนักงานและกรรมการได้ (READ_VIA) เพื่อใช้เลือกในตารางงาน
- อนุมัติคำขอลบงานประจำ (แม่บ้าน/สวน) = ยุติงานตั้งแต่วันนี้ เก็บประวัติและ KPI ไว้ (เหมือนปุ่มลบเดิม)

## การแจ้งเตือนผู้ตรวจ
- ช่างส่งงานทาง LINE (#ส่งงาน + รูป) ครั้งแรก -> แจ้งผู้ตรวจของเมนูงานซ่อมและ admin ที่ผูก LINE ไว้ ถ้าไม่มีใครผูก ส่งเข้ากลุ่มเดิม
- คำขอลบใหม่ -> แจ้งผู้ตรวจ/admin ทาง LINE และเด้งบนเว็บ (ป้ายตัวเลขบนเมนู "คำขอลบข้อมูล") ผลพิจารณาแจ้งกลับผู้ขอ
- ผูก LINE: โปรไฟล์ -> แท็บ "LINE แจ้งเตือน" -> ขอรหัส -> พิมพ์ `#ผูกบัญชี รหัส` ในแชทส่วนตัวกับบอท

## ผู้ตรวจเห็นเฉพาะงานที่ได้รับมอบหมาย (งานซ่อม / งานแม่บ้าน / งานสวน)
- ใบงานซ่อมมีช่อง "ผู้ตรวจงาน" ใหม่ และตารางงานแม่บ้าน/สวนเปลี่ยนช่อง "หัวหน้างานผู้ตรวจ" เป็นเลือกจากบัญชีผู้ตรวจจริง
- ผู้ตรวจ (inspector) เห็น แก้ ลบ ตรวจ อนุมัติ และดู KPI ได้เฉพาะงานที่ตนเองเป็นผู้ตรวจ บังคับที่เซิร์ฟเวอร์ (access.js, dailyTasks.js, index.js)
- admin เห็นทุกงานและเป็นคนเดียวที่เปลี่ยนผู้ตรวจของงานเดิมได้ ช่างเลือกผู้ตรวจตอนสร้างงานได้ แต่เปลี่ยนภายหลังไม่ได้
- ผู้ตรวจที่สร้างงานเอง ระบบผูกกับตัวเองให้อัตโนมัติ
- งานที่ยังไม่ระบุผู้ตรวจ (เช่น งานซ่อมที่แจ้งทาง LINE) ผู้ตรวจจะไม่เห็น เห็นเฉพาะ admin และช่าง จนกว่า admin จะมอบหมาย
- งานแม่บ้าน/สวนเดิมที่มีชื่อผู้ตรวจเป็นข้อความ: `npm run db:init` จะจับคู่กับบัญชีผู้ตรวจที่ชื่อที่แสดงตรงกันเพียงบัญชีเดียวให้อัตโนมัติ (ต้องสร้างบัญชีผู้ตรวจก่อนแล้วรัน db:init อีกครั้ง) ที่เหลือ admin มอบหมายเอง
- แจ้งเตือน LINE ตอนช่างส่งงานซ่อม/คำขอลบ ส่งเฉพาะผู้ตรวจของงานนั้นและ admin
- คำขอลบของงานซ่อม/แม่บ้าน/สวน ผู้ตรวจเห็นและอนุมัติได้เฉพาะงานของตัวเอง
- ตัวเลขรวมบนหน้าภาพรวม (/stats, /kpi) ยังเป็นยอดรวมทั้งระบบ ไม่แยกตามผู้ตรวจ

## รูปประกอบการตรวจงานแม่บ้าน/คนสวน
- ตอนกด "ตรวจงาน" มีช่อง "รูปประกอบการตรวจ" แนบได้สูงสุด 3 รูป (ย่อรูปในเบราว์เซอร์อัตโนมัติ) แก้ผลตรวจแล้วเพิ่ม/ลบรูปได้
- รูปแสดงเป็นภาพย่อในคอลัมน์ผลการตรวจ กดดูภาพใหญ่ได้ ยกเลิกผลตรวจ = ลบรูปตาม
- ค่าเริ่มต้น "ไม่บังคับ" ถ้าต้องการบังคับแนบทุกครั้ง ใส่ `REQUIRE_INSPECT_PHOTO=1` ใน .env แล้วรีสตาร์ท
- ตารางใหม่ daily_task_log_photos (อยู่ใน schema.sql รัน `npm run db:init`)
